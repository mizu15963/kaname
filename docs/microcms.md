# microCMS

microCMS は **お問い合わせの保存（`contacts`）にだけ** 使います。記事・カテゴリは今回の要件にないため作りません。ページの中身は各ページのファイルに書くので、ビルドは microCMS を読みません（microCMS の設定がなくてもビルドは通ります）。

## サービスを作る（最初に1回）

1. microCMS にログインし、**サービスを作成** → サービス名とサービスID を決める。サービスID が `MICROCMS_SERVICE_DOMAIN`（管理画面の URL `https://<サービスID>.microcms.io` の `<サービスID>`）になる。
2. 下の「API の作り方」で `contacts` を作る。
3. 下の「API キー」のとおり権限を付けたキーを用意する。
4. Cloudflare の **実行時の変数** に入れる（[contact.md](contact.md) の「設定の手順」）。

## API

| API | エンドポイント | 形式 | 項目の定義 |
|---|---|---|---|
| お問い合わせ | `contacts` | リスト形式 | [schema/contacts.json](../schema/contacts.json) |

- `schema/` のファイルは microCMS の「スキーマの書き出し」と同じ形式です。API を作るときに、このファイルをインポートして項目を作ります。
- 管理画面で項目を変えたら、スキーマを書き出して `schema/` のファイルを上書きしてください（フォームの項目名と選択肢はこのファイルから読むので、選択肢を変えてもコードは直さなくてよい）。

## contacts（お問い合わせ）

フォームから送られた内容を下書きで保存します（サイトには公開されません）。フォームの作りは [contact.md](contact.md)。

| フィールドID | 表示名 | 種類 |
|---|---|---|
| `name` | お名前 | テキストフィールド |
| `email` | メールアドレス | テキストフィールド |
| `category` | お問い合わせ種別 | セレクトフィールド（TODO(仕様): 選択肢を決める） |
| `message` | お問い合わせ内容 | テキストエリア |

## API の作り方

1. 管理画面で **API を作成** → **自分で決める**（またはスキーマのインポート）を選ぶ。
2. API 名「お問い合わせ」、エンドポイント `contacts`、リスト形式を選ぶ。
3. `schema/contacts.json` をインポートする。インポートできなかった項目は、上の表のとおり手で作る。

## API キー

キーはチャットやリポジトリに書かず、手元の `.dev.vars` と Cloudflare の実行時の変数にだけ入れてください。

| キー | 権限 | 使う場所 |
|---|---|---|
| `MICROCMS_API_KEY` | `contacts` の **POST のみ** | お問い合わせフォームの保存（Worker の実行時） |

`contacts` に GET を付けません（キーが漏れても、お問い合わせの個人情報を読み出されないように）。

## Webhook

- `contacts` の **メール通知** で、お問い合わせが届いたことを知らせる（[contact.md](contact.md) の「設定の手順」）。
- デプロイフックは登録しない（お問い合わせのたびに再ビルドされるため）。
